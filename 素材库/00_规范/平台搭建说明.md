# 平台搭建说明（M3–M4）

记录 `app/` 工程的骨架、构建链、PWA 与验收办法。素材规格见 `素材清单与制作规范.md`，配音见 `配音切分说明.md`，整体节奏见 `方案/儿童诗词互动平台_方案_v0.2.md`。

## 一、工程与运行

- 工程位置：`app/`，Vite + React + TypeScript，hash 路由（不用 history，子路径部署不会 404）
- 开发：`cd app && npm run dev`
- 构建：`cd app && npm run build` → `app/dist`
- 预览：`cd app && npm run preview -- --port 4173 --strictPort`
- 画布：1024×768 死画布，`Frame` 组件按 `min(vw/1024, vh/768)` 等比缩放，任何尺寸都不滚动

## 二、目录与数据流

```
素材库/  ──►  工具/build_assets.py  ──►  app/public/assets/  ──►  dist/assets/
素材库/  ──►  工具/make_content.py  ──►  app/src/content/poems/*.json
```

- `build_assets.py`：场景图 1773×1330 → 1440×1080 WebP，单张 ≤120KB（q82 起，超限降到 q76/q70）；贴纸 q90；角色、闭眼 patch、环境层保透明 WebP；配音 WAV → AAC 96kbps。产物 121 个文件、8.0MB
- `make_content.py`：唯一的内容源。逐字拼音（pypinyin + 人工覆盖，带错位断言）、逐句释义、三条讲稿、lead、scenes/sticker/audio 字段
- 改诗文的正确姿势：改 `make_content.py` 里的 POEMS 表 → 重跑脚本 → 重跑 build

## 三、路由与页面

| 路由 | 页面 | 行为 |
|---|---|---|
| `#/` | 诗库 | 5×2 十张卡，封面用 s1，遮罩上标编号·朝代与诗名 |
| `#/p/0X` | 诗主页 | 大标题 + 作者 + 一句 lead（纸底便签）+ 读/看/讲/玩四圆钮 |
| `#/p/0X/read` | 读 | 左侧纸页四句大字带拼音，点句读句，底部「听整首 / 看画面」 |
| `#/p/0X/look` | 看 | 满屏场景 + 底部深色渐变压字；点画面进下一句，末句点进玩；带重听与四点指示 |
| `#/p/0X/talk` | 讲 | 左「这首诗在说什么」整首+逐句释义，右「讲给孩子听」三条讲稿 |
| `#/p/0X/play` | 玩 · 第一关 | 排一排：四槽 + 四张乱序卡，点对入槽并播该句，点错抖动，四句齐后自动进第二关 |
| `#/p/0X/find` | 玩 · 第二关 | 找一找：每首取三句各挖一个汉字，六个字里挑对的那个，点对补字并播该句，点错抖动，三字齐后跳完成 |
| `#/p/0X/done` | 完成 | 贴纸 pop 动画 + 记 finished + 播整首；三个去向 |
| `#/stickers` | 贴纸册 | 10 格，已收显示贴纸，未收显示问号 |

进度存 `localStorage` 的 `poem-book-v1`，结构 `{ finished: string[], stickers: string[] }`。音频由 `lib/audio.ts` 统一管：单实例、首次 `pointerdown` 解锁、`playAudio(src, onEnd)`，切页时 `stopAudio()`。

## 四、PWA

- `public/manifest.webmanifest`：`display: standalone`、`orientation: landscape`、纸底 `#FFF7EC`、192/512/maskable 三枚图标（用 01 号贴纸压出来的）
- `public/sw.js`：install 阶段读 `precache-manifest.json` 全量 `addAll`；activate 清旧缓存；fetch 走 cache-first，导航失败回落到 `index.html`
- `工具/make_precache.py`：构建后扫描 `dist` 生成清单（排除 `sw.js` 自身），当前 **131 个文件 / 8.50MB**
- 注册只在生产构建（`import.meta.env.PROD`），开发时不注册，避免缓存干扰
- 构建顺序固定为 `npm run build` → `make_precache.py`；顺序反了清单就是空的

## 五、验收

1. 逐页截图：`chrome --headless=new --virtual-time-budget=5000 --window-size=1024,768 --screenshot=<绝对路径> http://localhost:4173/#/<路由>`，共八张，存 `素材库/_预览/v3-*.png`
2. 离线：`工具/test_offline.py`（连 `--remote-debugging-port` 的无头 Chrome，等 `serviceWorker.controller`、数 `nuanshi-v1` 缓存条目、`Network.emulateNetworkConditions` 切离线后重新导航 + 截图）。实测结果：控制页面 True、缓存 131 条、离线仍能打开并渲染
3. 目录三类问题人工走查：点句读句、点画面翻句、错卡抖动、收贴纸后贴纸册变化

## 六、踩过的坑

- **截图会拍在半路**：不加 `--virtual-time-budget`，后几张封面图还是空的，看起来像图片没加载
- **`py -3.12` 与本机相关**：这台机器上 `py` 已不可用，Python 一律用全路径
- **SW 里不能写 `new URL(p, './')`**：base 必须是绝对 URL，改成 `self.registration.scope`
- **冷启动测离线会假阴性**：预热进程被强杀后立刻断网打开，页面会是白屏；规范做法是在同一进程内先确认 `controller` 再切离线
- **贴纸页展示依赖进度**：无头截图是全新 profile，所以贴纸册截图永远全是问号，不代表功能坏
- **Pages 的 Folder 必须选 `/docs`**：Source 选 main 但目录留在 `/ (root)` 时，GitHub 会用 Jekyll 把仓库根的 `README.md` 渲染成首页，打开站点看到的是一篇文档而不是应用；切换目录后不需要改代码，`base: './'` 自带相对取资源
