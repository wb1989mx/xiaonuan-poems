## 三、规格

**场景图**

| 项 | 规格 |
|---|---|
| 母版 | PNG，1773×1330（4:3），单张 2.7–3.5MB |
| 构建产物 | WebP q82，1440×1080，单张 ≤120KB |
| 安全区 | 主体压在画面中部，四周各留 8% 不放关键元素 |
| **上部留空** | 上三分之一必须留空，否则诗行压到鹿角上 |

**角色**：透明 PNG 母版，构建时转 WebP。归一后头宽 260px。

**贴纸**：512×512 透明 PNG，圆形徽章、赭石细描边；圆外全透明，小投影不烘进图里，交给 CSS（`border-radius:50%` + `box-shadow`），换背景不用重出图。单张 342–365KB，构建时转 WebP q90 约 60KB。

**音频**：交付 WAV 48k/24bit 单声道、响度归一到 −16 LUFS、峰值 ≤−3dBFS → 构建时转 AAC 96kbps m4a（单句约 60KB）。每首 5 个（`XX-1..4` + `XX-full`），十首 50 个、合计 37.3MB；切分方法与十首对应表见 `配音切分说明.md`。

**母版策略**：素材库存**高质母版**（3MB 的 PNG 照原样留着），压缩只发生在构建时、输出到 `app/public`。不要为了省空间压母版。

## 四、角色怎么拆层（已按实测改写）

前两版方案都失败了，记在这里免得重走。

**失败一：分部件生成。** 分别出 body 和 head，结果躯干是侧后视、头是正脸，头还比身体大一圈。分开生成时模型各自决定朝向和比例，不会替你对齐，拼起来不是一只鹿。

**失败二：一张全身图沿颈线横切。** 横切线放在哪个高度都得穿过藤编书箩，切出来是两截。

### 4.1 定稿方案：整鹿单层

| 层 | 内容 | 动效 |
|---|---|---|
| 1 | 整只小暖（含围巾、书箩） | 呼吸缩放 1.016 + 整体轻摆 −1.8°，支点在脚底 |
| 2 | 闭眼 patch（每姿态左右两只各一张） | 睁眼为底图，闭眼叠上去 150ms 再撤，随机 3–6 秒一次 |
| 3 | ~~围巾尾端~~ | 不单独切，随身体整体摆动（见 §4.6） |

睁眼态就是整鹿图本身，不另存；闭眼态只把眼睛那一小块换成弧线，其余像素一个不动。所以这一层没有任何接缝可担心。

代价要看清：**不能做头部独立转动，也不能做四肢关节动画。** 换来的是三个姿态各一张图就能全搞定，而且永远不会有接缝。

### 4.2 出图与抠图（已跑通）

1. 纯色品红做背景，出**整只鹿**。不要白底——小暖身上有奶油色梅花斑和心形臀斑，白底抠图会把斑点一起抠掉
2. 脚本自动从四角取样背景色。生图给的"品红"每张都不同，从荧光品红 (252,20,182) 到偏玫瑰 (217,71,111) 都出现过，硬编码色值必然失败
3. 按到背景色的欧氏距离键控，阈值 18 / 68，边缘羽化
4. 裁到内容外框，存 PNG 透明

实现在 `工具/key_and_preview.py`。实测一张 1536×1536 的图：全透明约 69%、实体约 24%、羽化边缘约 7%，放大 200% 无品红残留。

### 4.3 三条美术约束（比画得好看更重要）

- 平涂、少阴影、边界清晰
- 不用叠色渐变、厚涂笔触、复杂毛理
- 轮廓线必须闭合、边缘锐利——羽化键控最怕毛边

### 4.4 验收

1. 抠完放大 200%，轮廓无品红描边
2. 静帧与动帧叠在一起比，颜色不发灰、不偏粉
3. 眼睛 patch 换上去，眼位不跳、眼白不露

### 4.5 三姿态必须归一（实测新增）

三个姿态是分三次生成的，模型给的头身比各不相同：sit 脸大身子短、stand 拉高一截、walk 又细长。并排一看就是三只不同的鹿。

**归一方法：按"头宽"缩放。** 头部（含双耳）宽度是唯一与姿态无关、又能反映角色体量的量。取包围盒顶部 42% 区域里最宽的一行作为头宽，三张统一缩放到同一头宽（当前 260px），再按脚底对齐。

实测三张原始头宽 595 / 474 / 505 px，缩放系数 0.44 / 0.55 / 0.51。

脚本：`工具/poses_sheet.py`。**每加一个新姿态，都要重跑一次归一**——提示词管不住比例。

**残留问题**：归一后坐姿仍比站姿小约一成，肉眼可辨但不跳。要更严得回到"同一张图变形出各姿态"，成本高，先接受。

### 4.6 闭眼 patch：为什么最后是画出来的，不是生成的

目标是"同一张脸上换一个眼睛状态"。试过三条路，只有第三条稳。

**路一：让模型局部改眼，整张回贴。** 出的图本身画得很好，但回贴必翻车——模型重绘时把头局部放大了约 3%（相对身体），眼睛相对鼻子发生漂移；同时整块矩形贴回去，四边接缝在放大后清晰可见。用内容框做相似变换能对齐整体，却修不了这个局部差。

**路二：只保留眼区像素，做椭圆柔和过渡。** 接缝能压住，但闭眼弧线的位置仍会跟着漂移一点点，而且皮肤明暗与周围接不上，会留下一圈浅色圆盘。

**路三（定稿）：程序化重画。** 定位眼球 → 用上下边界插值把眼球填成皮肤 → 在填好的皮肤上画眼睑弧线与睫毛。

- 对齐由构造保证，不存在漂移
- 只覆盖眼球那一片，没有矩形边界
- 弧线粗细、拱高、睫毛位置都是参数，改起来是改数字

三个技术细节，都是踩过才定下来的：

1. **眼球是"暗椭圆 + 一圈白月牙"，不是一个色块。** 白月牙长在瞳孔圆外侧，所以掩膜取暗块与白块的**凸包**再外扩 6px，才盖得住整只眼。只取暗块会漏出一条白眼白。
2. **填色不能各向同性外推。** 眼睛正上是棕色眉弓、正下是桃色脸颊，全局平均会糊成一片浅色圆盘。改成**逐列取上下最近有效像素做距离加权插值**，颜色天然带着这张脸的明暗梯度。
3. **颗粒要补回来。** 填过的区域是平滑的，周围有纸纹；按原图"减去小半径模糊后的残差标准差"量出颗粒强度，再叠回去，才不显得那块是"贴上去的"。

实现在 `工具/eye_patch_draw.py`，输出 `eye-close_{pose}-{1,2}.png` 与 `10_分层/eye_patch.json`（含每张 patch 的放置坐标）。

**为什么围巾尾端不切了。** 尾端挂在胸前、压在身体和书箩上，切下来后旋转 ±6°，原位会露出一个身体上的窟窿——补这个窟窿要么生成一张"无尾身体"（全图重绘、整只鹿都可能漂），要么手工补，两条都不划算。而尾端跟随身体的整体轻摆本来就有动感。所以这一层取消，围巾作为整鹿的一部分一起摆。

肉眼验收口径：**按 1024×768 画布上 380px 的呈现高度看**，不能按原图 100% 看。真机尺寸对照见 `_预览/眨眼_真机尺寸.png`——那个尺寸下接缝与填色都看不出来。150ms 的眨眼，也不给人盯着看的机会。

### 4.7 场景图的生产配方（批 3 定型）

一张场景图 = **一张姿态母版当参考图 + 一段四节式提示词**。母版提供脸和配色，提示词提供场景与站位；鹿是被重绘进场景的（带接触阴影），不是抠图贴上去。

四节固定，顺序不变，每节不留空：

1. **风格**（每条一模一样）：横版儿童绘本插画，暖阳水粉与彩铅质感，纸面细颗粒，笔触干净、边缘清楚；暖赭棕 / 奶油 / 苔绿 / 天青 / 暖橘，暗部墨绿与赭石；光从左上斜射；禁纯黑纯白高饱和红蓝
2. **场景**：分层写——上三分之一是什么、中间是什么、下三分之二是什么，各层的颜色都点到
3. **主体**：位置（中下部偏左/右）、**高度约占画面一半**、朝向、视线落在哪个意象上；再写一段"严格沿用图一的脸与毛色"，把眼睛、鼻梁、腮红、额头小斑、梅花斑、心形臀斑、短鹿角、天青围巾、藤编书箩逐项点名；最后写"去掉图一的品红色背景 + 落在哪里 + 接触阴影"
4. **完成度**：平涂为主、少阴影、轮廓锐利；留白；不出现任何文字、不加多余装饰

**批 3 踩到的五个坑，都写进配方了：**

| 现象 | 原因 | 对策 |
|---|---|---|
| 鹿只占不到三成高，像远景路人 | 只写"画面中下部"没写尺度 | 明写"高度约占画面一半" |
| 脸成了纯侧脸，认不出是同一只 | 侧向 + 看向画面侧被读成 90° | 明写"四分之三侧面、两只眼睛都看得见" |
| 额头小斑、心形臀斑消失 | 只写"保持一致"太笼统 | 逐项点名五官与斑纹 |
| 前腿腾空的"跃立" | "抬起前蹄"被读成 prance | 明写"四蹄全部着地，不要腾空" |
| 诗行位置被深色树冠压住 | 上三分之一只是"留空"，没说不放深色物 | 明写"上三分之一只有浅色天空，不放深色景物" |

尺寸一律 1773×1330；同一条线四张图共用同一个姿态母版（`sit` / `stand` / `walk`），姿态要跟句子里的动作对得上——站着的句子别用坐姿母版。

**每批只查四件事**：色板有没有跑偏、主光是不是都从左上来、留白够不够、脸还是不是那张脸。

**冷调题材的量化兜底**：雪景、夜景、瀑布这类天生偏冷的画面，光靠眼睛判断会放过冷偏。取全图最亮 3% 像素的平均色，看 **B−R**：负值才是暖的。十首实测，其余九首都在 −13 到 −38，只有《江雪》四张落在 −8 到 −11、《望庐山瀑布》三张在 −8 到 −12——仍是暖的，只是浅一档，正好对应"天寒"。没有一张出现正值，不需要调色。

**《江雪》第二张有个刻意的取舍**：句意是"万径人踪灭"，画面里却留了小暖自己的蹄印。人踪灭了，鹿踪不必也灭，反而让孩子看明白雪地里"没有别人来过"。

### 4.8 贴纸：让模型先画圆，再由程序抠圆

贴纸不能靠"生成透明底"——模型给的透明边缘会带一圈奶油色毛边。可行的分工是：**模型负责画一枚画在奶油纸上的圆徽章，程序的圆遮罩负责裁**。

提示词固定三句：整幅底色奶油纸色、正中一枚圆徽章直径占八成、圆外什么都不放。十张一次过，只有《登鹳雀楼》重出（原图前蹄抬起像悬空）。

后处理 `工具/stickers.py` 四步：取四角中位色当纸色 → 找与纸色相差 >15 的像素包围盒（徽章是画面唯一异物）→ 以包围盒圆心重裁方形，圆外留 6% → 4 倍超采样画圆遮罩再缩回，得到抗锯齿的透明边。出口 512×512，342–365KB。

**圆心不用追问模型**。生成的图圆心普遍偏一格，全部由程序按包围盒重定，这一步不能省——否则十枚贴在贴纸册上会看出高低。

**投影不烘进图里**。透明 PNG 只给圆，`border-radius:50%` + `box-shadow` 由页面加，这样深色底、浅色底都不用重出图。

## 五、环境层（不阻塞）

九类：云飘、水面波光、树影光斑、落叶、灯焰、细雨、落雪、鸟群、雾起。每类 2 帧，共 18 张、合计 0.70MB。

| 类 | 文件 | 尺寸 | 画法 |
|---|---|---|---|
| 云飘 | `01_云飘/01-{1,2}.png` | 900×320 | 程序：扁平底椭圆 + 3–4 个大小不等的顶包，底部一层暖赭灰 |
| 水面波光 | `02_水面波光/02-{1,2}.png` | 900×200 | 程序：细长高光点，少量天青 |
| 树影光斑 | `03_树影光斑/03-{1,2}.png` | 900×520 | 程序：暖黄光斑 + 苔绿暗斑，大半径模糊 |
| 落叶 | `04_落叶/04-{1,2}.png` | 900×640 | 程序：椭圆叶 + 短叶柄，四种落色，随机旋转 |
| 灯焰 | `05_灯焰/05-{1,2}.png` | 126×220 / 165×220 | **模型生成**（透明底），按不透明包围盒裁边 |
| 细雨 | `06_细雨/06-{1,2}.png` | 640×640 | 程序：一根 1px 斜线，倾角约 9° |
| 落雪 | `07_落雪/07-{1,2}.png` | 640×640 | 程序：暖灰底影 + 近白亮面 |
| 鸟群 | `08_鸟群/08-{1,2}.png` | 520×320 | 程序：一笔两翼的浅 V，全幅 20–30px |
| 雾起 | `09_雾起/09-{1,2}.png` | 900×300 | 程序：纵向余弦剖面 × 横向正弦相位，交叠 5 条 |

**为什么八类不交给模型**：环境层是纯叠加物，必须满足两条硬要求——边缘是全透明、图案左右或上下能首尾相接。模型给的透明边会带一圈奶油毛边，画的云与雨也没法环绕，进页面一动就露馅。程序绘制两个都天生满足，而且每张 15–40KB。

**两个绕不开的坑**：

1. 纯白叠加在浅色天空上会消失。所有叠加物都得是双色结构——亮面近白，下面垫一层很淡的暖灰/暖赭。落雪尤其明显，只有一层暖灰底影才在雪地和浅天上看得见。
2. 云不能只把圆叠在一起，会变成"胶囊"。必须有扁平底 + 顶上一串大小不等的顶包，才有云的剪影。

**雾和落雪在浅色天空上几乎看不见，这是对的**，不要为了"看得见"去加大不透明度——它们的任务是让深色的山脚、水面变柔，不是在天上画白烟。

**怎么动**：每类两张做相位差，CSS 关键帧把整层平移一个自身宽/高再跳回，两张以不同速度循环，就不容易看出周期。接口只认"环境层文件"，以后换成真实流体视频，页面代码不用改。

| 素材 | 位置 |
