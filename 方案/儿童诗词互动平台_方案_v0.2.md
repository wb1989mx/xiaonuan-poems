# 儿童诗词互动平台 · 方案设计 v0.2

## 0. 一句话定义

一本会动、会读、会玩的诗词绘本。孩子点开一首诗，一屏之内读完、听完、玩完，手指不需要划来划去。

## 2. 两条硬约束，决定后面所有设计

### 2.1 八岁孩子的认知

- 课标要求一二年级累计认识约 1600 字、会写约 800 字，实际参差很大 → **拼音必须常驻可开**
- 单页注意力 60–90 秒，超时就要换一个"动作"
- 指令只能一句话，不能靠小字说明 → 按钮图形化 + 语音提示
- 他要的不是"学习"，是"我完成了""我集到了" → 贴纸收集替代分数
- 手指精细度有限 → 点击热区 ≥ 88pt，拖拽吸附半径放大

### 2.2 iPad Safari 的真实限制

| 限制 | 后果 | 对策 |
|---|---|---|
| 无用户手势不能播放有声媒体 | 一进场静默 | 首屏"开始"按钮内做音频解锁 |
| 视频须 playsinline + muted 才能自动播 | 环境视频带声音会被拒 | 视频一律静音，声音走独立旁白音轨 |
| 100vh 随工具栏变化 | 布局抖动、出滚动条 | 不用 vh，改固定画布 + transform 缩放 |
| Safari 不支持方向锁 | 竖屏时版式错乱 | 横屏设计 + 竖屏时盖"把 iPad 横过来"提示层 |
| user-scalable=no 在 iOS 被忽略 | 误触双指缩放 | gesturestart preventDefault + touch-action |
| 长期不用会清理存储 | 离线缓存丢 | 壳必须能从网络重建，SW 缓存优先 |
| GitHub Pages 不能自定义响应头 | CSP、Cache-Control 设不了 | 缓存只能靠 SW + 文件名 hash |

## 3. 核心结构：一诗一屏 + 多级页面

### 3.1 怎么做到"绝不滚动"

设计基准画布 **1024 × 768（4:3）**。所有元素绝对定位塞进这张"纸"，整张纸等比缩放铺满可用区，四周多出来处用暖米色填平、描一道装饰边框。

```
html, body { overflow:hidden; position:fixed; inset:0; overscroll-behavior:none; }
stage.scale = min(vw / 1024, vh / 768)
```

从 9.7 寸到 13 寸、任何系统缩放比例，版式一模一样。代价是不做响应式断点——这一次，恰恰是优点。

### 3.2 页面树

**L1 首页 · 诗库**
每屏 8 首（4×2 卡片），翻页按钮，不滚动。完成/未完成两种状态一眼可辨。

**L2 诗主页**（每首诗固定一屏）
- 上：诗题、作者朝代、一句白话导语
- 中：主插画 + 小暖的微动效
- 下：四个大圆按钮 —— 读一读 / 看一看 / 讲一讲 / 玩一玩
- 左上返回、右上主页：全站固定位置、固定图标

**L3 读一读**
逐句大字版，一屏四句（绝句正好一屏）。点某句 → 播该句音频 + 该句高亮 + 关键意象小图浮现。

**L3 看一看**
逐句切换的定格画面（不是连续视频）。一句一屏画面，配呼吸与局部动效，画面之间 0.4 秒交叉淡入。底部用**进度点**不用进度条。

**L3 讲一讲**
注释卡，一屏三张（词义 / 画面注解 / 白话译文），"下一张"按钮翻页，卡片内部不滚动。

**L3 玩一玩**
互动题，一屏一题，共 2–3 题。

**L4 完成页**　点亮一枚贴纸 + "再玩一遍 / 换一首"

**L5 贴纸册**　收集页，同样分页不滚动

八岁孩子不认面包屑，只认两个门：左上"回去"、右上"回家"。这两个按钮的位置和图形，从第一屏到最后一屏一模一样。

### 3.3 一首诗的时长预算

选诗 10s → 读 60s → 看 40s → 讲 40s → 玩 60s → 完成 15s ≈ 4 分钟。刚好一段完整专注。

## 4. 美术规范：暖阳童年

### 4.1 色板（固定七色）

| 角色 | 色值 |
|---|---|
| 纸底 | `#FFF7EC` |
| 暖光 | `#FFD79A` |
| 主橘 | `#F6A96B` |
| 苔绿 | `#8FB573` |
| 天青 | `#A8D8DE` |
| 赭石 | `#B5714A` |
| 墨 | `#3E3229` |

大面积浅底 + 一处暖光高光 + 一点苔绿或天青呼吸。禁纯黑、纯白、高饱和红蓝。阴影用赭石降透明度，不用灰——灰一上，画面立刻从晨光变印刷品。

### 4.2 光与构图

- 一句诗一个画面，一个画面只讲一件事，中心只有一个主角
- 统一晨光或午后逆光，柔边，轻颗粒 2–4%
- 留白占画面 40% 以上
- 人物脸朝画面内侧，视线指向关键意象
- **夜景也要暖**：月是暖白偏黄，不是冷蓝；暗部用墨绿不用黑
- **每张场景图上三分之一必须留空**，否则诗行会压到鹿角上

### 4.3 分层可切性：美术的第一约束

- 平涂、少阴影、部件边界清晰
- 不用叠色渐变、厚涂笔触、复杂毛理
- 轮廓线必须闭合、边缘锐利——羽化键控最怕毛边

### 4.4 角色一致性

1. **打锚点**：一张四视图设定，冻死五官、鹿角、衣色、头身比
2. **参考图驱动**：之后每张图都拿锚点图当参考图送进豆包生图
3. **固定前缀 + 固定种子**：每条提示词前三句永远是同一段风格描述
4. **头宽归一**：详见 §5.2

### 4.5 文字

- 正文：霞鹜文楷（LXGW WenKai，OFL 开源），子集化 woff2 本地打包，**不引 CDN**
- 标题：思源宋体 Bold
- 1024 基准下：诗正文 56–64px / 行高 1.6、注释 32px、拼音 24px 居上

## 5. 动效管线：Flash 式有限动画

### 5.1 为什么不用视频分镜

Flash（剪贴动画 cut-out）的本质是**少量素材 + 关键帧补间**，不是逐帧重画。

| | 视频分镜 | Flash 式 |
|---|---|---|
| 单诗体积 | ≈5MB | ≈1.6MB（角色素材全站只算一次） |
| 制作机时 | 每首约 40 分钟，还要重出 | 角色素材做一次，全站复用 |
| 一致性 | 靠首帧图，仍有漂移风险 | 同一套素材，天然成立 |
| 修改成本 | 改就重出 | 改数值，秒级 |
| 能做 | 推拉摇移、复杂动作 | 只有微动，不能跑跳和运镜 |

对"简单动画 + 绘本翻页感"这个需求，右列完全够，左列的代价全是浪费。

### 5.2 素材规格（实测修订）

原本设想的"分部件生成再拼回"实测不成立：分开生成时模型各自选朝向和比例，躯干侧后视、头正脸、头还比身体大；改成"全身图沿颈线横切"也被书箩挡死，切口必然穿过藤编。

定稿为**整鹿单层**：

| 层 | 文件 | 内容 | 动效 |
|---|---|---|---|
| 1 | `full-{pose}.png` | 整只小暖（含围巾、书箩） | 呼吸 1.016 + 整体轻摆 −1.8°，支点脚底 |
| 2 | `eye-close_{pose}-{1,2}.png` | 闭眼 patch，每姿态左右各一张 | 睁眼为底，闭眼叠 150ms 再撤，随机 3–6 秒 |
| — | ~~围巾尾端~~ | 不单独切，随身体一起摆 | — |

姿态三个：`sit` / `stand` / `walk`，各一张品红底原图 + 一张透明 PNG。

代价：做不了头部独立转动和四肢关节动画，围巾也不能单独飘。换来的是三个姿态各一张图、永远没有接缝。

**闭眼是画出来的，不是生成的。** 让模型改眼再回贴，试了两版都不行：模型会把他头局部放大、眼睛相对鼻子漂移，矩形贴回去四边有接缝。定稿改成程序化：定位眼球 → 用逐列上下插值填成皮肤 → 画眼睑弧线与睫毛。对齐由构造保证，只覆盖眼球那一片，没有矩形边界。细节见 `素材库/00_规范/素材清单与制作规范.md` §4.6。

**验收按真机尺寸看**：1024×768 画布上角色约 380px 高，那个尺寸下接缝看不见；按原图 100% 看会放大出并不存在的问题。

**头宽归一**：三张图是分三次生成的，头身比各不相同（实测头宽 595 / 474 / 505 px）。以头部含双耳宽度为基准统一缩放到 260px（系数 0.44 / 0.55 / 0.51），再按脚底对齐，三张才像同一个角色。

**抠图**：生图给的品红每张不同（实测出现过 (252,20,182) 和 (217,71,111) 两种），硬编码色值必失败。每次从四角取样背景色，再按距离键控，阈值 18/68。

### 5.3 关键帧表

| 动作 | 参数 | 周期 |
|---|---|---|
| 呼吸 | 身体 scale 1.016，头部同步上浮 2px | 2.4s 循环 |
| 眨眼 | 眼 patch 切换 | 随机 3–6s |
| 轻摆 | 整体 ±1.8° | 4s 循环 |
| 围巾飘（可选） | ±6° 旋转，锚点颈侧 | 1.8s，与呼吸错相 |

存成 `deer-motion.json`，页面只读数值。改快慢就改数字，不碰美术。

### 5.4 环境循环素材

九类：云飘、水面波光、树影光斑、落叶、灯焰、细雨、落雪、鸟群、雾起。每条 4 秒、首尾帧对齐、1024×768、≤400KB，合计 ≤3.5MB，全站复用。

**已落地（v1）**：每类 2 张静态透明 PNG，CSS 反向位移循环，18 张合计 **0.70MB**。八类由程序绘制（`工具/environment.py`，天然可无缝环绕、真透明边），灯焰由模型生成透明底后裁边。以后接视频模型替换，页面只认"环境层文件"，不认来源，接口不变。

**一条实测出来的规矩**：叠加物必须是双色结构——亮面近白，底下一层很淡的暖灰/暖赭。纯白在浅色天空上等于消失。雾与落雪在浅天上的低可见度是物理正确的，不要为了"看得见"而加不透明度。

### 5.5 诚实说局限

Flash 式做不了推拉镜头和复杂动作。所以"看一看"页面的信息量不能靠运镜，要靠**逐句换画面**：一句一个定格，配呼吸与局部动效，画面之间 0.4 秒交叉淡入。

这反而是对的——视频模型做"四句诗连贯演一遍"很难，做出来常显得假；"四张画面 + 淡入"完全够，也正是绘本翻页的节奏。

## 6. 音频与朗读：真人录制

**录法：一首一条，十首十条，不录导语。** 交付 10 个整段录音（手机 m4a 即可），切成 50 个文件由程序完成（`工具/split_voice.py`）。

一首之内按固定顺序念，段间留静默：句一 →2s→ 句二 →2s→ 句三 →2s→ 句四 →4s→ 整读 →结束。停顿期间不出声、不挪手机、不吞口水，程序靠"被语音夹住的长静默"找切点（≥1.2 秒才认）。

**为什么整首连录**：四句的气息连贯，听着才像一个人在旁边念；分五次录再拼，音量与语气每句都微微跳，耳朵听得出来。

**为什么不要导语**：开场那句"这首诗是七岁小哥哥写的"本来只是引子，念出来反而抢了读诗的静气；改成页面上的文字，孩子自己看，也省 10 个文件、省一次录音里的口误风险。

**切分与验收**：检出最长的 4 段静默取中点切，每段首尾压到 0.2 秒静音，响度归一到 −16 LUFS，输出 48kHz / 24bit 单声道；同时出一张波形图，把切点与每段时长标出来供人复核。切不干净的只重录那一首，退路是那一首改逐句录。

**实测修订（2026-11-25）**：第一批十条录音实际是「带导语、句间只停 0.3–0.5 秒」，上面那条静默切法整批失效（扫码最长静默仅 0.96 秒）。改走识别对齐：本地 faster-whisper 出词级时间戳 → 掐掉导语 → 四句与识别字串加权对齐取句界 → 中点切。十条已切完 50 个文件并回读校验通过。结论：**停顿守规矩时走静默切（确定性、无需识别）；停顿不足时只能走识别对齐**，两条链路都留在 `工具/` 下。细节见 `素材库/00_规范/配音切分说明.md`。

**保留**：`xx-audio.json` 记录每段起止与文件名，页面与校对都用它。

- 语速 4–4.5 字/秒，五言绝句整读 12–16 秒，宁慢勿快
- 峰值不超 −3dBFS；**不要后期调语速**
- 一次录十首嗓子会塌，分两次，每次五首

详见 `素材库/00_规范/配音文案_十首.md`。

**同步策略**：只做句级。点第 N 句播第 N 个文件并高亮该句，不做字级时间轴。整读时用累计时长推算当前句，误差 ≤0.3 秒。

**拼音**：`pinyin-pro` 离线跑一次生成 ruby 标注写进 JSON；**多音字必须人工校对**（曲、觉、藏、露、长、更），以孩子学校用的版本为准。

## 7. 技术架构

### 7.1 选型

**Vite + React + TypeScript**，构建产物纯静态，直接丢 GitHub Pages。多级路由、进度状态、组件复用都有现成解法；体积代价约 45KB gzip。

分层动画用 CSS transform 驱动，不做 canvas 逐帧——iPad 上更稳，也更好调试。

### 7.2 目录

```
儿童学习平台/
├─ app/                     # 前端工程（待建）
├─ content/poems/*.json     # 内容源，与代码解耦
├─ 素材库/
│   ├─ 00_规范/             # 配音文案、素材清单
│   ├─ 共用_角色/00_锚点/、10_分层/{sit,stand,walk}/
│   ├─ 共用_环境/
│   ├─ 诗词/01..10/{场景,音频,贴纸}/
│   └─ _预览/               # 过程预览，不进构建
├─ 工具/                    # 抠图、归一、压图脚本
├─ 方案/
└─ README.md
```

### 7.3 关键实现点

- **路由用 hash**（`#/poem/01/read`）：GitHub Pages 纯静态，history 模式一刷新就 404
- **PWA**：manifest（`standalone`、`landscape`、180×180 图标）+ SW（壳预缓存、媒体 cache-first、配额 60MB、LRU）
- **视频**：`<video playsinline muted preload="none" loop>` 只做背景层
- **预加载**：只预取下一首或下一屏的 1–2 个资源
- **进度**：localStorage 存完成状态与贴纸，不上传

### 7.4 体积预算

| 项 | 预算 |
|---|---|
| 首屏壳 | ≤1.5MB |
| 角色素材（全站一次） | ≈0.6MB（3 张整鹿 + 6 张闭眼 patch，patch 合计 61KB） |
| 环境素材（全站一次） | **实测 0.70MB**（18 张静态 PNG） |
| 单首诗（4 张场景 + 5 段音频 + 贴纸） | ≈1.6MB（场景图 WebP q82 每张 ≤120KB） |
| **20 首全量** | **≈30MB** |

比视频分镜方案的 140MB 小一个数量级，整站可以全量离线预缓存。20 首从 37MB 下调到 ≈30MB，是因为环境素材走静态图版、且场景图按 1440×1080 出图转 WebP。

### 7.5 境内访问

| 路径 | 做法 | 优点 | 代价 |
|---|---|---|---|
| A（推荐） | 代码在 Pages，媒体放 Cloudflare R2 / 阿里云 OSS | 加载快，换源不动代码 | 需域名；国内加速要备案 |
| B | 全量 Cloudflare Pages | 一个平台、免备案 | 境内速度一般 |
| C | 局域网自建 | 零成本零延迟，开发期试玩 | 只能在家；HTTP 下 SW 不注册 |

37MB 全量预缓存意味着路径 C 的分量很重——局域网跑一遍装进 iPad，之后走到哪都能离线用，开发期完全不需要公网。

## 8. 内容格式

```json
{
  "id": "02",
  "title": "静夜思",
  "author": "李白",
  "dynasty": "唐",
  "lead": "一个人在外地，看见月亮就想家了",
  "lines": [
    { "text": "床前明月光", "pinyin": "chuáng qián míng yuè guāng", "audio": "02-1.wav" },
    { "text": "疑是地上霜", "pinyin": "yí shì dì shàng shuāng", "audio": "02-2.wav" }
  ],
  "scenes": [ { "line": 1, "img": "02-s1.webp", "deer": "sit" } ],
  "notes": [ { "word": "疑", "mean": "好像、仿佛", "img": "n02-1.webp" } ],
  "translation": ["明亮的月光洒在床前，", "好像地上结了一层霜。"],
  "play": [
    { "type": "order", "lines": ["床前明月光", "疑是地上霜", "举头望明月", "低头思故乡"] },
    { "type": "find", "targets": [{ "x": 0.32, "y": 0.55, "word": "明月" }] }
  ],
  "sticker": "02-sticker.webp"
}
```

`deer` 字段只填姿态名（`sit` / `stand` / `walk`），不写坐标。`lead` 只作页面文字，不配音；`audio` 每句一个文件，另有一份 `xx-full.wav` 供整读。

玩法本期只做两种：
- **排一排**：打乱四句拖回正确顺序，拖错轻轻弹回，不给红叉
- **找一找**：在插画页找三个意象热区，点中浮出词和读音

只做两种的原因：类型越多，每种磨得越浅。

## 10. 风险与取舍

1. **分层可切性** —— 实测两版失败，代价已经付过。整鹿单层是当前最优解，别再回头切颈线。
2. **Flash 式的表现上限** —— 不能跑跳运镜。这决定"看一看"必须是逐句定格 + 淡入。
3. **三姿态体量差** —— 归一后坐姿仍比站姿小约一成。要更严得走"同一张图变形"，成本高，先接受。
4. **录音返工** —— 十首四十句，规矩没先讲清就得重录。
5. **多音字** —— 读错一次孩子就学错，人工校对不可省。
6. **授权** —— 唐宋诗词公有领域；教材的注释、译文、赏析有版权，一律自写。字体走 OFL 并留 LICENSE。
7. **注释口径** —— 以教材或主流说法为准，不引入学界争议。
8. **不做 AI 朗读评分** —— 童声识别误差大，误判伤积极性。
